# Local Development Setup

Get the Tridel Technologies website running on your machine in under 5 minutes.

---

## Prerequisites

| Tool | Minimum version | Check |
|------|----------------|-------|
| [Node.js](https://nodejs.org/) | v18+ | `node --version` |
| [npm](https://www.npmjs.com/) | v9+ | `npm --version` |
| Git | any | `git --version` |

> **Windows users:** PowerShell 5.1+ is required for the optional build script. It ships with Windows 10/11.

---

## 1. Clone the repository

```bash
git clone <repo-url>
cd Tridel-main-clone
```

---

## 2. Install dependencies

```bash
npm install
```

This installs two runtime packages — `express` and `cors`. There is no build step required for local development.

---

## 3. Environment variables (optional)

The server works out of the box without any environment file. A random admin password is generated and printed to the terminal on every start.

If you want a **fixed** admin password, create a `.env.local` file in the project root:

```env
# .env.local  (never commit this file — it is already in .gitignore)
TRIDEL_ADMIN_PASSWORD=your-password-here
```

| Variable | Default | Description |
|----------|---------|-------------|
| `TRIDEL_ADMIN_PASSWORD` | *(auto-generated, printed to console)* | Admin panel login password |
| `TRIDEL_ADMIN_PASSWORD_HASH` | — | Pre-hashed password (production use only) |
| `ADMIN_ENABLED` | `true` | Set to `false` to disable the admin panel entirely |

---

## 4. Start the server

```bash
npm start
```

The terminal will print something like:

```
WARNING: TRIDEL_ADMIN_PASSWORD is not set.
Generated one-time development admin password for this server process: xK9#mP2...
Tridel server running at http://127.0.0.1:3000
```

> **Note the one-time password** if you plan to use the admin panel in this session.

---

## 5. Open in browser

| URL | What it is |
|-----|-----------|
| `http://localhost:3000` | Main public website |
| `http://localhost:3000/#/simulation` | Strait of Hormuz Simulation |
| `http://localhost:3000/admin` | Admin / Content Management panel |

> The admin panel is only accessible on `127.0.0.1` / `localhost`. It is automatically blocked on any other host.

## Editing content

All website content lives in `assets/js/*-data.js` flat files — no database required.

**Option A — Admin panel (recommended):**
1. Open `http://localhost:3000/admin`
2. Log in with the password shown in the terminal
3. Edit content through the UI
4. Click **Save Local Files** to write changes back to disk

**Option B — Direct file edit:**
Open any `assets/js/*-data.js` file in your editor and edit the exported JS object. Changes are live-reloaded by the browser (hard refresh may be needed).

## Simulation data

The simulation uses pre-fetched Copernicus Marine (CMEMS) oceanographic data stored in `simulation/data/chunks/`. These files cover the Strait of Hormuz region and are committed to the repository — **no CMEMS account is needed to run locally.**

The simulation uses three physics tracks:

| Track | Scenarios |
|-------|-----------|
| **Search & Rescue (Leeway)** | S&R fast response · Wide uncertainty search · Long horizon drifting object |
| **Oil Spill** | Diesel leak · Light crude release · Heavy fuel shoreline risk |

## FormSubmit (contact & careers forms)

The site uses [FormSubmit.co](https://formsubmit.co/) — a free, no-backend email service — to handle the **Contact** and **Careers** form submissions.

### How it works

```
Browser form submit
      │
      ▼
POST /api/form-proxy          ← same-origin request (avoids CORS)
      │
      ▼
server.js proxies to
formsubmit.co/ajax/<email>    ← HTTPS to FormSubmit's servers
      │
      ▼
FormSubmit emails the
configured inbox
```

The server proxy (`/api/form-proxy`) exists purely to sidestep the browser CORS restriction on direct `formsubmit.co` requests. The proxy reads the destination email from `assets/js/settings-data.js` at submission time, so changing the email in the admin panel takes effect immediately without a restart.

---

### Destination emails

Configured in `assets/js/settings-data.js`:

```js
const SETTINGS_DATA = {
  "contactEmail": "mail@trideltechnologies.com",
  "careersEmail": "careers@trideltechnologies.com",
  ...
};
```

You can update these through the **Admin → Global Settings** panel, or by editing the file directly.

| Form | `settings-data.js` key | Hardcoded fallback |
|------|------------------------|-------------------|
| Contact (`/contact`) | `contactEmail` | `mail@trideltechnologies.com` |
| Careers (`/careers`) | `careersEmail` | `careers@trideltechnologies.com` |

---

### First-time activation (important)

FormSubmit requires a **one-time email confirmation** the first time a new destination address is used.

1. Submit the Contact or Careers form once from the live site.
2. Check the inbox of the destination email address.
3. Click the **Activate Form** confirmation link from FormSubmit.
4. From that point on, submissions are delivered without further action.

> If you change `contactEmail` or `careersEmail` to a new address, you must re-activate that address by repeating the steps above.

---

### Hidden fields sent with every submission

| Field | Value | Purpose |
|-------|-------|---------|
| `_captcha` | `false` | Disables FormSubmit's built-in CAPTCHA page redirect |
| `_template` | `table` | Formats the email body as a neat HTML table |
| `_subject` | `"New Contact Message - Tridel Website"` | Sets the email subject line (contact form only) |

---

### Testing forms locally

FormSubmit works over the internet — there is **no local mock**. When running on `localhost`:

- Form submissions still route through `/api/form-proxy` → `formsubmit.co` → email.
- The destination address must already be activated (see above).
- If you want to test without sending real emails, temporarily set `contactEmail` / `careersEmail` to a personal address you control, activate it once, and submit away.

> **Tip:** Use a service like [Mailinator](https://www.mailinator.com/) or [Temp Mail](https://temp-mail.org/) for throwaway test inboxes during development.

---

### Changing the destination email

**Via admin panel (recommended):**
1. Go to `http://localhost:3000/admin`
2. Open **Global Settings**
3. Update **Contact Email** or **Careers Email**
4. Click **Save Local Files**

**Via direct file edit:**
Open `assets/js/settings-data.js` and update `contactEmail` or `careersEmail`.

After changing to a new email address, remember to activate it with FormSubmit before expecting submissions to arrive.

## Common issues

**Port 3000 already in use**
```bash
# Find what's using port 3000
# macOS / Linux
lsof -i :3000
# Windows
netstat -ano | findstr :3000
```
Kill the process, then run `npm start` again.

---

**"Page failed to load" on a page**
The router lazy-loads page scripts. If the server isn't running, script fetches will fail. Make sure `npm start` is running before navigating.

---

**Admin panel not accessible**
The admin panel is hard-blocked on any host other than `127.0.0.1`. Accessing via your machine's LAN IP (e.g. `192.168.x.x`) will return 404. Use `http://localhost:3000/admin` or `http://127.0.0.1:3000/admin`.

---

**Simulation shows blank / white map**
The simulation CSS is loaded from three separate files in `simulation/css/`. If one fails to load (e.g. wrong working directory), the dark theme won't apply. Check the browser Network tab to confirm all three CSS files return 200.

## Production build (optional)

The `dist/` folder is a flattened production copy of the public site (no server-side code). To regenerate it:

```powershell
# Windows PowerShell
npm run build
```

This runs `scripts/build-public.ps1` and copies/minifies assets into `dist/`. You don't need this for local development.

## Tech stack

| Layer | Technology |
|-------|-----------|
| Server | Node.js + Express |
